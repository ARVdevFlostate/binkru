# Release Plan Checklist

## 1. Purpose

This checklist assists reviewers in evaluating whether a Release Plan conforms to the Product System governance, Release Plan Methodology and Release Plan Template.

It is intended to support consistent review prior to approval.

---

# 2. Scope

This checklist applies to all Release Plan artifacts governed by the Product System.

---

# 3. Review Checklist

## Artifact Identity

- [ ] An Artifact ID has been assigned.
- [ ] A Release ID has been assigned.
- [ ] Product information has been completed.
- [ ] Version information is present.
- [ ] Ownership is identified.
- [ ] Approval information has been completed or is ready for approval.

---

## Release Summary

- [ ] The Release Summary is clearly stated.
- [ ] The summary accurately reflects the purpose of the release.
- [ ] The summary communicates intended customer and business value.
- [ ] The summary avoids implementation activities.

---

## Strategic Context

- [ ] The strategic context is clearly described.
- [ ] The Release Plan aligns with the Product Vision.
- [ ] The Release Plan reflects approved Product Decision Records.
- [ ] The Release Plan aligns with the Product Roadmap.
- [ ] The Release Plan aligns with the Milestone Plan.

---

## Release Scope

- [ ] The release scope is clearly defined.
- [ ] Product Capabilities are clearly identified.
- [ ] Release scope supports one or more milestones.
- [ ] Included Epics have been identified.
- [ ] Delivery priorities are appropriate.
- [ ] Target Release Window is appropriate where provided.

---

## Release Plan Readiness

- [ ] Release Plan readiness has been evaluated.
- [ ] Scope readiness has been considered.
- [ ] Dependency readiness has been considered.
- [ ] Business readiness has been considered.
- [ ] Operational readiness has been considered.
- [ ] Customer readiness has been considered.

---

## Assumptions

- [ ] Significant assumptions have been documented.
- [ ] Assumptions are relevant to the Release Plan.

---

## Constraints

- [ ] Significant constraints have been documented.
- [ ] Constraints relevant to the planned release are appropriately reflected.

---

## Risks

- [ ] Significant release risks have been identified.
- [ ] Risks appropriately reflect release planning.
- [ ] Risks are consistent with the Release Plan.

---

## Success Characteristics

- [ ] Success Characteristics are clearly described.
- [ ] Success Characteristics support the Product Vision.
- [ ] Success Characteristics focus on delivered customer and business value rather than implementation activities.

---

## Related Artifacts

- [ ] The Product Vision has been referenced.
- [ ] Relevant Product Decision Records have been referenced.
- [ ] The Product Roadmap has been referenced.
- [ ] The Milestone Plan has been referenced.
- [ ] References are accurate.

---

## Governance

- [ ] The Release Plan is traceable to the Product Vision.
- [ ] The Release Plan is traceable to approved Product Decision Records.
- [ ] The Release Plan is traceable to the Product Roadmap.
- [ ] The Release Plan is traceable to the Milestone Plan.
- [ ] The Release Plan clearly communicates Product release intent, scope, objectives and expectations.
- [ ] The Release Plan does not establish implementation activities or Engineering delivery commitments.
- [ ] The Release Plan provides a governed Product planning foundation for subsequent Product artifacts.
- [ ] The Release Plan has undergone appropriate review.
- [ ] The Release Plan is ready for Product Owner approval.

---
