# Release Plan Composition Specification

## 1. Purpose

This specification defines how a Release Plan is composed within the Product System.

It establishes the governed inputs, composition process and expected output for producing a Release Plan artifact.

This specification supports consistent composition by both humans and AI assistants.

---

# 2. Scope

This specification applies to all Release Plan artifacts governed by the Product System.

It complements:

- Release Plan Methodology
- Release Plan Template
- Release Plan Checklist
- Product Artifact Model

---

# 3. Composition Principles

Composition of a Release Plan shall:

- produce a complete Release Plan artifact;
- conform to the Release Plan Template;
- follow the Release Plan Methodology;
- satisfy the Release Plan Checklist;
- align with the Product Vision;
- align with approved Product Decision Records;
- align with the Product Roadmap;
- align with the Milestone Plan;
- preserve release traceability; and
- preserve human ownership of Product release intent, scope and expectations.

---

# 4. Composition Inputs

A Release Plan may be composed using:

## Required Inputs

- Product Vision
- Product Decision Records
- Product Roadmap
- Milestone Plan
- Release Plan Template
- Release Plan Methodology

The Release Plan shall reflect the approved strategic direction, product outcomes and milestone planning.

## Optional Inputs

Where available, composition may consider:

- previous Release Plans;
- business objectives;
- customer research;
- stakeholder feedback;
- market analysis;
- organisational priorities;
- known constraints relevant to the planned release;
- lessons learned; and
- known dependencies relevant to the planned release.

The availability of optional inputs depends on the product context.

---

# 5. Composition Process

Composition should generally perform the following activities:

1. Review the Product Vision.
2. Review approved Product Decision Records.
3. Review the Product Roadmap.
4. Review the Milestone Plan.
5. Identify release scope.
6. Identify Product Capabilities.
7. Associate Product Capabilities with milestones.
8. Identify included Epics.
9. Evaluate release dependencies.
10. Assess Release Plan readiness.
11. Document assumptions, constraints and risks.
12. Identify related artifacts.
13. Populate the Release Plan Template.
14. Validate against the Release Plan Checklist.

Composition is iterative and may revisit earlier activities as product understanding evolves.

---

# 6. Composition Output

The output of composition is a completed Release Plan that:

- conforms to the Release Plan Template;
- satisfies the Release Plan Checklist;
- aligns with the Product Vision;
- aligns with approved Product Decision Records;
- aligns with the Product Roadmap;
- aligns with the Milestone Plan;
- preserves release traceability;
- establishes an authoritative Product planning artifact for the intended scope and objectives of the release; and
- is ready for Product Owner review and approval.

---

# 7. Human and AI Responsibilities

Humans are responsible for:

- defining Product release intent and expectations;
- defining Product Capabilities;
- determining release scope;
- validating Product Release Plan readiness; and
- approving the Release Plan.

AI may assist by:

- analysing milestone outcomes;
- identifying Product Capabilities;
- recommending release scope;
- analysing known release dependencies;
- assessing Product Release Plan readiness;
- identifying inconsistencies;
- checking completeness;
- validating traceability; and
- validating conformance.

AI does not determine Product release intent, scope or expectations, or approve the Release Plan.

---

# 8. Relationships

This specification composes a Release Plan using governed Product System assets.

Each Release Plan shall be traceable to:

- the Product Vision;
- approved Product Decision Records;
- the Product Roadmap; and
- the Milestone Plan.

Completed Release Plans become governed inputs to subsequent product artifacts including:

- Epics;

The Release Plan communicates Product release intent and expectations rather than implementation activities or Engineering delivery commitments.

---

# 9. Conformance

Composition conforms to this specification when:

- required inputs have been considered;
- the Release Plan Template has been completed;
- the Release Plan Methodology has been followed;
- the Release Plan Checklist has been satisfied;
- release traceability has been preserved;
- human ownership has been preserved; and
- the Release Plan is ready for approval.
